# Development Diary - October 2026

## 2026-10-05: What the black-ground marker could not see

On 04/10/2026 the g_generals black-terrain fix landed (PR #17, merge
`a756c3c`): the base game never got the `__ANDROID__` guard that Zero Hour
received on 01/08/2026, so `m_multiPassTerrain` defaulted to FALSE on
Android and `AlphaTerrainTextureClass::Apply()` took the single-pass
shortcut whose own comment says *"This method is a backdoor specific to
Nvidia based cards. It will fail on other hardware."* -- and no mobile GPU
is Nvidia. Both `apk-generals` and `apk` checks went green on PR #15.

Then a tester sent a screenshot of still-black terrain plus a device log
showing `GX-BUILD-MARKER 20260801-multipass-terrain-fix m_multiPassTerrain=1`.
Three things had to be untangled before that log meant anything:

1. **Which build was running.** `CI build number: 71`, compiled
   `Oct 3 2026 13:05:37`, build id `3d179608...`. Run 71 is
   `Build Android (Zero hour)` at head `c2a4c009` (the build id is PR #15's
   `refs/pull/15/merge` sha, which is why no branch carries it) -- built
   ~23 hours *before* the fix merged. It is the ZH APK; the running engine
   is `z_generals`, whose own marker has printed since August. The log said
   nothing about g_generals.

2. **What the marker actually proves.** It prints in the *constructor*.
   `MultiPassTerrain` is also a field of `s_GlobalDataFieldParseTable`
   (GlobalData.cpp:100/107), and `GlobalData::parseGameDataDefinition()`
   applies every `GameData` block *after* the constructor: the BIG-archived
   `Data\INI\GameData.ini` (via `initSubsystem` in `GameEngine::init`),
   `SagePatch.ini`, any repacked or modded game-data INI, and map overrides
   through `INI_LOAD_CREATE_OVERRIDES`. A ctor marker of `=1` therefore
   does not describe the value the renderer branches on. Vanilla retail data
   ships `MultiPassTerrain = Yes` in both games (checked against the
   archived retail INI), but the device runs a "Steam Edition" repack, and
   nothing enforced the invariant against data that says otherwise.

3. **What the renderer sees.** Only two call sites consume the flag
   (`TerrainTex.cpp:546` and `:1058`), and neither ever logged.

So the follow-up landed the same day: both games now log the value each
`GameData` file parsed (`GX-GAMEDATA`, attributed with
`ini->getFilename()`) and re-assert `TRUE` on Android at that point -- the
last place the INI machinery can reach the field -- and the shared
`AlphaTerrainTextureClass::Apply()` prints a one-time `GX-TERRAIN-PASS`
line with the value the draw actually branched on. One device run now
distinguishes "INI flipped it back", "binary is stale" and "multipass is
not the cause" instead of leaving all three looking identical.
