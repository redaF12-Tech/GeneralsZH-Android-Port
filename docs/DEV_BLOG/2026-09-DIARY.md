# Development Diary - September 2026

---

## 2026-09-20: Daylight/Darkmode for the Android launcher

The launcher (Setup / folder picker / log viewer / GeneralsOnline
account) had shipped dark-only since the launcher-ui-2026 rework —
`Theme.Material3.Dark` with one near-black palette in
`res/values/colors.xml`. The user-facing ask was an in-app
Daylight/Darkmode choice.

Why not `AppCompatDelegate.setDefaultNightMode()`: the app
deliberately has no `androidx.appcompat` dependency (every Activity
extends plain `android.app.Activity` — same reasoning as
`LocaleHelper`'s manual `attachBaseContext` language wrap), and
`AppCompatDelegate` is an appcompat class. So the override is done
with the platform mechanism directly:

- New `ThemeHelper` (mirror of `LocaleHelper`): a `ui_mode` int in the
  same `generalszh_setup` prefs (0=system/absent, 1=daylight, 2=dark),
  and a `wrap()` that overrides only the `UI_MODE_NIGHT_*` half of
  `Configuration.uiMode` via `createConfigurationContext()`.
- Every launcher Activity now calls
  `super.attachBaseContext(ThemeHelper.wrap(LocaleHelper.wrap(base)))`.
  `LocaleHelper` stays the outer wrap it always was (it snapshots the
  configuration it is given), so the language override keeps
  authority; ThemeHelper only touches the night half.
- The theme parent moved to `Theme.Material3.DayNight`, which keeps
  Material's internal widget shading (switch tracks, slider, ripples)
  coherent in both halves — a fixed-Dark parent over a light palette
  would not.
- Palette split: the original dark set moved verbatim to
  `res/values-night/colors.xml`; `values/` now carries the daylight
  palette (M3 baseline purple-40 primary, matching surface-container
  ladder, status colours retuned for a light ground). No Java or theme
  name changed — every consumer already read tokens through
  `UiKit.color()` / theme attributes, so both halves resolve by name.
- The per-mode bits that cannot live in the palette file:
  - `android:windowLightStatusBar` now points at a bool resource
    (`gzh_light_system_bars`, true in daylight).
  - `Theme.GeneralsZH.AlertDialog` (the plain
    `android.app.AlertDialog`s) has a light framework parent in
    `values/` and a dark parent re-declared in `values-night/` — the
    two parents cannot be swapped through an attribute. Every other
    item is identical; only the parent differs.
- UI: a "Theme" card (system / Daylight / Darkmode as a segmented
  row, current answer as the header value) at the top of Setup →
  Interface, above Language. Applying is `recreate()` — the same flow
  the language picker uses, and safe because every Activity re-wraps
  its base context in `attachBaseContext()`.
- Strings in all 13 launcher languages, including the Arabic/Farsi
  RTL locales; the card is start/end-relative like everything else.

The game surface (`GeneralsZHActivity`) is untouched: it keeps its
own fullscreen theme, and the palette files were already comments-only
to it.

Validation: XML well-formedness across all touched res files; visual
check of both palettes pending a device build (CI: Build Android).
